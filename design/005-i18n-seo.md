# 多语言页面与收录

## 1. 背景与目标

- 当前问题：图酷原先只有简体中文。安装包和网页使用同一份页面，公开站点需要被不同语言的搜索引擎和生成式引擎收录。
- 目标用户与场景：Windows 安装包用户按系统语言使用；浏览器用户通过地址或顶栏切换语言；公开站点让每种语言有稳定、可互指的地址。
- 成功标准：同一份 `apps/web` 构建同时服务安装包和 Docker。11 种语言都有独立 HTML、hreflang、sitemap 和 `llms.txt`。原有中文地址保持不变。
- 非目标：不做第二套界面，不把推理放进浏览器，不按 `Accept-Language` 给爬虫跳转，不做博客、支付或登录。

## 2. 现状与约束

- 文案类型来自 `apps/web/src/content/zh.ts` 的 `Copy`。语言表在 `apps/web/src/locale.ts`，这份文件不依赖 Vue，构建插件可以直接引用。
- 语种与原 easyimage 站点一致，代码也保持一致：`en`、`zh`、`zh_hant`、`es`、`de`、`ja`、`pt_br`、`hi`、`vn`、`ar`、`bn`。越南语的地址前缀是 `vn`，语言标记是 `vi-VN`。
- 产品名在每种语言里都是「图酷」。证件照像素、社交尺寸、50MB、同源 `/api/engine` 等事实在各语言中保持一致。
- 默认语言与原站不同。原站默认英语并给其他语言加前缀。图酷已经公开的地址是无前缀中文，所以默认语言改为简体中文，中文继续不带前缀。

## 3. 方案概览

地址是网页语言的依据。简体中文使用 `/compress` 这类现有路径，其他语言使用 `/en/compress`、`/zh_hant/compress`。`/zh` 重定向到无前缀中文，避免出现两套中文地址。`x-default` 指向无前缀中文。

网页不读取 `Accept-Language`。爬虫没有 `localStorage`，因此不会被根地址重定向。用户在顶栏选过语言后，键 `tucools-locale` 只在再次打开 `/` 时生效。安装包里存在 `window.tucools`；第一次打开 `/` 且没有保存语言时，才按 `navigator.languages` 匹配系统语言。

构建时为每种语言的每个路由写一份 `index.html`，并写出带 xhtml 互指的 `sitemap.xml`，以及每种语言的 `llms.txt` 和 `llms-full.txt`。nginx 先找目录下的 `index.html`，语言前缀找不到具体页面时回退到该语言首页。安装包的静态服务使用同一套查找顺序。

## 4. 详细设计

### 4.1 数据模型与权威来源

`catalogs.ts` 以 `LocaleCode` 索引全部文案。运行时 `copy` 是响应式对象，切换语言时整包替换。导航分组在菜单 store 内按当前文案计算，避免在模块加载时把中文标签固定下来。工具页的 `RouterView` 使用完整路径作为 key，切换语言后重新读取文案。

### 4.2 收录

每个可索引路径在 sitemap 中出现 11 次，并带全部语言的 `hreflang` 和 `x-default`。首页加 19 个工具，共 220 条。功能菜单每种语言都有页面，但 `noindex`，不进入站点地图。

未设置站点根时，规范地址是站内路径。浏览器运行后改成 `window.location.origin`。构建参数 `VITE_SITE_URL` 和容器变量 `TUCOOLS_SITE_URL` 使用同一个不带路径的 `http` 或 `https` 根地址。容器入口只替换仍以 `/` 开头的规范地址、hreflang、JSON-LD 和收录链接，不改 `/assets/` 样式地址，也不会把已经是绝对地址的链接再加一遍前缀。

### 4.3 从右到左

阿拉伯语设置 `dir="rtl"`。侧栏使用逻辑方向 `start`，并在样式里让桌面宽度取消滑出位移，避免从右到左时侧栏停在屏幕外。

## 5. 风险与取舍

- 不按浏览器语言跳转会让第一次访问的网页用户先看到中文，除非他们打开带前缀的地址或之后从根地址进入。这样可以避免爬虫被重定向到错误语言。
- 预渲染不是动态服务端渲染。关闭 JavaScript 后可以阅读该语言的说明，不能在页面里处理图片。
- 站点地图不按 `TUCOOLS_FEATURES` 删减。隐藏的工具地址仍然可以被公开抓取。
