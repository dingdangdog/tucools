# 工具页独立地址与收录

多语言收录见 `design/005-i18n-seo.md`。本文第 4.5 节「只提供 zh-CN」已被该方案替代。

## 1. 背景与目标

- 当前问题：路由已经是 `/compress`、`/cutout` 这样的独立地址，但服务器对所有地址返回同一份 `index.html`。标题和说明只在 JavaScript 运行后写入。不执行脚本的搜索引擎和生成式引擎只能看到首页。
- 目标用户与场景：公开部署的图酷站点希望每个工具被单独收录；安装包和本机 Docker 仍使用同一份页面。
- 成功标准：每个工具地址的首份 HTML 自带标题、说明、canonical、结构化数据和常见问题。`sitemap.xml`、`robots.txt`、`llms.txt`、`llms-full.txt` 随构建生成。浏览器里的工具操作保持原样。
- 非目标：不改成 Nuxt 或多页应用，不做多语言，不做博客，不新增第二套界面，不把引擎暴露到公网。

## 2. 现状与约束

- 现有架构、组件和数据源：Vite + Vue Router history。文案在 `apps/web/src/content/zh.ts`。nginx 使用 `try_files $uri $uri/ /index.html`。Electron 静态服务在文件不存在时回退到根 `index.html`。
- 技术、兼容、安全、合规和发布约束：同一份 `apps/web` 构建给 Docker 和安装包。公开域名在构建镜像时未知，绝对地址只能在容器启动时补上。
- 已知历史问题：客户端路由已经会改 `document.title` 和 description，这只对执行 JavaScript 的抓取程序有效。

## 3. 方案概览

收录数据以 `apps/web/src/content/zh.ts` 的 `seo` 和工具标题为唯一文案来源，`apps/web/src/seo.ts` 生成头部、JSON-LD、无脚本说明和四个收录文件。构建时按路由写出 `压缩/index.html` 这类页面。浏览器运行后用当前域名把规范地址改成绝对地址。容器只在设置了合法的 `TUCOOLS_SITE_URL` 时，把站点地图和 `llms.txt` 里的站内路径换成绝对地址。

## 4. 详细设计

### 4.1 数据模型与权威来源

每个可访问路径对应一条说明：标题、描述、是否进入站点地图、最多两个常见问题。首页和 19 个工具进入站点地图。`/menus` 保留独立地址，但标记 `noindex`，因为它只保存这台设备的显示选择。未知地址使用「页面不存在」，同样 `noindex`。

### 4.2 API、权限与错误语义

无新接口。`TUCOOLS_SITE_URL` 只接受不带路径的 `http` 或 `https` 根地址，非法值忽略并写到容器日志。

### 4.3 状态、缓存、并发与幂等

收录文件在构建时生成，容器启动时按环境变量重写。重复启动会再次替换已经写成绝对地址的链接；替换规则只匹配站内路径，不会把绝对地址再加一遍前缀。

### 4.4 UI、交互与信息架构

工具页原有操作不变。常见问题放在批量页底部，或对照页侧栏的可滚动区域里，默认收起。首页在工具列表后显示同一组问题。不执行脚本时，`noscript` 里保留该页标题、说明、问题和工具链接。

### 4.5 国际化、主题与响应式

只提供 `zh-CN`。页面声明 `hreflang="zh-CN"` 和 `x-default`，两者指向同一地址。常见问题使用现有文字和边框令牌，明暗主题都能读。

### 4.6 日志、审计、隐私与安全

说明文字写明哪些工具在浏览器本地完成，哪些只请求同源 `/api/engine`。不新增上传，不记录访问。

## 5. 失败与恢复

- 外部依赖失败：没有公开域名时，规范地址保持站内路径，页面仍可打开。
- 部分成功：某个工具缺少说明时，路由启动会抛出错误，避免只给一半地址做收录。
- 重试与幂等：重新构建或重新创建页面容器即可重写收录文件。
- 用户恢复路径：未知地址提供回到开始的链接。

## 6. 兼容与发布

- 旧地址保持不变。
- 安装包里的静态服务改为优先返回该目录自己的 `index.html`，这样桌面端打开 `/compress` 时也能拿到这一页的说明。
- 不需要数据库迁移。

## 7. 验证与发布前置

- `npm run typecheck` 和 `npm run build:web`。
- 检查构建结果中 `/compress` 与首页的标题不同，站点地图不含 `/menus`。
- 在浏览器里打开首页、一个本地工具和一个 AI 工具，确认常见问题可见，地址栏仍是独立路径。
- 未创建 Docker 容器，因此没有在容器里实测 `TUCOOLS_SITE_URL` 的替换。替换规则与构建文件中的站内路径对应。

## 8. 明确不做

- 不按 `TUCOOLS_FEATURES` 从站点地图删除工具。限制功能的部署不应把站点公开给搜索引擎。
- 不做服务端渲染出完整的可操作界面。脚本关闭时只能读到说明，不能在页面里处理图片。
