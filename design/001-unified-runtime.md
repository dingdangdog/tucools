# 图酷双端运行时设计方案

## 1. 背景与目标

- 当前问题：图酷桌面用 Electron IPC 调用三个一次性推理程序；EasyImage 用 Nuxt 在浏览器里做图像工具。两套界面、两套部署，无法共用。
- 目标用户与场景：需要在自己的电脑上安装使用，或在一台机器上用 Docker 打开浏览器使用的人。
- 成功标准：同一份页面覆盖原有图像工具；抠图、超分、消除走同一套 HTTP 契约；`docker compose` 提供浏览器入口；Windows 安装包在本机打开同一份页面。
- 非目标：激活、支付、试用次数、博客、广告、11 语 SEO、上色、美颜、人脸修复、macOS 与 Linux 安装包。

## 2. 现状与约束

- 图酷算法在 `engine_code` 的 rembg、LaMa 和 upscayl-bin 调用里。模型包约 1GB，单独发布和下载，不进安装包，也不进 Docker 镜像。
- EasyImage 的像素处理不依赖服务端。Nuxt、Content 和 sqlite 只服务博客与 SEO，本次不保留。
- 超分依赖对应平台的 `upscayl-bin`。Linux 容器不能运行 Windows 可执行文件。
- 消除依赖 torch，抠图依赖 onnxruntime。两套旧 requirements 的 torch 版本冲突，统一引擎不安装 Python 版 realesrgan。

## 3. 方案概览

界面只有一份 Vite + Vue 静态站点。浏览器内工具在页面里完成。AI 工具只请求同源 `/api/engine`。Docker 的 nginx 和安装包里的本地静态服务都把该路径转到引擎。算法以 `services/engine` 的 Python 服务为权威实现；Windows 上若已有旧 `.runtime` 可执行文件，桌面网关只按原命令行转交，不复制算法。

## 4. 详细设计

### 4.1 数据模型与权威来源

- 工具目录与中文文案：`apps/web/src/content/zh.ts`。
- 浏览器图像算法：`apps/web/src/utils`。
- AI 任务没有账号数据库。任务文件只存在引擎临时目录，下载或超时后删除。
- 模型包是独立目录，由 `TUCOOLS_MODEL_PACK` 指定。权重在其 `models/`，超分程序在其 `bin/<平台>/`。文件清单见 `deploy/model-pack.json`。

### 4.2 API、权限与错误语义

无登录。引擎只监听本机，或只在 Compose 网络内可达。

- `GET /api/engine/health`：各工具是否就绪、缺少的文件、设备。
- `POST /api/engine/cutout|enhance|erase`：创建任务。忙时 409。缺模型或参数不合法时 400，正文说明缺什么。
- `GET /api/engine/jobs/{id}/events`：SSE，报告排队、处理中、完成或失败。
- `GET /api/engine/jobs/{id}/result`：结果文件。

上传上限 50MB，只接受常见图片。消除还需要蒙版 PNG。

### 4.3 状态、缓存、并发与幂等

引擎同时只处理一个任务。模型在进程内缓存到下次任务。失败后可以再次提交。页面不把引擎地址写死，开发时由 Vite 代理，部署时由宿主反代。

### 4.4 UI、交互与信息架构

工作台：左侧是工具目录，右侧是当前工具。分组为「本地处理」和「AI 处理」。

视觉主调是工业实用，辅助是单色加重点色和紧凑排版。背景用暖纸色，强调色用深青，不用紫蓝渐变、玻璃拟态或等大营销卡。暗色是可切换主题，不是默认皮肤。

每个工具具备空状态、处理中、失败原因和结果下载。AI 工具在引擎未就绪时说明缺少的文件，而不是禁用后不解释。

### 4.5 国际化、主题与响应式

界面为简体中文，文案集中在 `zh.ts`。主题为 light / dark，记在 localStorage。窄屏收起侧栏，用按钮打开工具列表。

### 4.6 日志、审计、隐私与安全

引擎日志不记录图片内容。本地工具不上传。不要把引擎端口映射到公网。安装包把引擎绑在 127.0.0.1。

## 5. 失败与恢复

- 外部依赖失败：缺模型、缺 upscayl-bin 或推理进程退出时，健康检查和任务错误写明文件或退出信息。
- 部分成功：一个工具不可用不影响其他工具。
- 重试与幂等：任务失败后可重新提交；没有扣费状态。
- 用户恢复路径：把单独下载的模型包解压到健康检查给出的目录，刷新后再处理图片。

## 6. 兼容与数据处理

- 存量数据：不迁移激活缓存和浏览器站点内容。
- 旧客户端：桌面可把 `TUCOOLS_RUNTIME` 指到旧 `.runtime`，调用原来的 `erembg.exe`、`eenhance.exe`、`eerase.exe`。
- 无数据库迁移。
- 回滚边界：新仓库独立，不改两个旧项目。

## 7. 实施顺序

1. 固定本设计与仓库边界。
2. 迁入浏览器工具和中文工作台。
3. 提供 Python 引擎与桌面旧命令行网关。
4. 接上三个 AI 页面。
5. 补齐 Docker、Windows 安装包、部署说明和变更记录。

## 8. 验证与验收

- `vue-tsc` 与 Python 语法编译。
- 引擎健康检查在依赖就绪时返回各工具缺失项。
- 浏览器里走通一个本地工具的选择、处理和下载。
- 未安装 torch 时不把推理写成已跑通。

## 9. 风险与待决策

| 项目 | 影响 | 建议 | 决策状态 |
| --- | --- | --- | --- |
| Docker 超分需要 Linux 版 upscayl-bin | 只有 Windows 二进制时超分不可用 | 健康检查指出缺少的文件 | 已接受 |
| 安装包不内置 PyTorch | 没有引擎二进制时 AI 需旧 runtime 或本机 Python | 页面说明未就绪原因 | 已接受 |
| 无登录的引擎 | 暴露端口即可被调用 | 文档要求只在本机或内网使用 | 已接受 |
