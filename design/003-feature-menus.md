# 功能菜单与模型停用

## 1. 背景与目标

- 当前问题：侧栏和首页总是列出全部工具。部署方不能按场景收起菜单。AI 页面在缺模型时仍能选图并提交，失败后才看到引擎报错。
- 目标用户与场景：用 Docker 或安装包提供图酷的人，希望只露出一部分工具；安装包用户希望在本机开关菜单；使用抠图、优化、消除的人在没有对应模型时立刻知道不能用，并知道去哪里下载。
- 成功标准：`TUCOOLS_FEATURES` 为逗号分隔的功能名时，导航、首页和直接打开的地址都只保留这些功能。客户端另有「功能菜单」页，选择写入本机。某个 AI 功能没有可用模型时，不能选图或开始处理，并显示仓库与发布页。
- 非目标：不做账号、远程同步或第二套界面。不把模型打进安装包或镜像。不在引擎里写发布地址。

## 2. 现状与约束

- 同一份 `apps/web` 构建给 Docker 和安装包用。页面在构建后不能读取进程环境变量，所以名单要在提供页面的进程里注入。
- 客户端由 `window.tucools` 识别。浏览器部署没有这个对象。
- 引擎 `GET /api/engine/health` 已经按工具返回 `ready`、`missing`、`available`。抠图和优化在至少有一个可用模型时 `ready` 为真。
- 模型与客户端新版本的发布位置暂定为 `https://github.com/dingdangdog/tucools/releases`。

## 3. 方案概览

功能名以 `apps/web/src/nav.ts` 的 `id` 为唯一名单。提供页面的进程把环境变量原样放进 `GET /app-config.json` 的 `features` 字符串。页面解析后得到允许显示的上限。未设置或空字符串表示不限制。

客户端在上限之内再用 `localStorage` 键 `tucools-features` 记录本机选择。没有本机记录时，显示上限内的全部功能。浏览器不读写这份缓存，只服从环境变量。

AI 页面打开时读取对应工具的健康状态。检查结束前和没有可用模型时，禁止选图和开始处理。没有可用模型时给出仓库和发布页。

## 4. 详细设计

### 4.1 数据模型与权威来源

功能名：

`compress`、`resize`、`converter`、`cropping`、`id-photo`、`sizes`、`cutting`、`watermark`、`caption`、`fade`、`tocircle`、`exif`、`pdf`、`favicon`、`prompt`、`pix`、`cutout`、`enhance`、`erase`。

`/app-config.json`：

```json
{ "features": "compress,cutout" }
```

`features` 为空字符串表示全部允许。未知功能名忽略。字符串非空但没有一个已知功能名时，不显示工具。

本机缓存是 JSON 字符串数组，只保存当前允许范围内、用户留下的功能名。

### 4.2 API、权限与错误语义

`/app-config.json` 由三个提供页面的入口生成，不经过引擎：

- 开发时由 Vite 读取 `TUCOOLS_FEATURES`。
- Docker 页面容器启动时写入静态文件。
- 安装包由 Electron 宿主读取启动时的环境变量。

响应带 `Cache-Control: no-store`。文件缺失或超时按「不限制」处理，避免配置接口故障把工具全部藏掉。

### 4.3 状态、缓存、并发与幂等

页面挂载前先读取配置。客户端再读取本机缓存。

可见功能 = 环境变量上限 ∩ 本机选择。没有本机选择时等于上限。直接访问未显示功能的地址时回到首页。「功能菜单」和首页不参与这道限制。

本机选择只在用户改勾选时写入。`显示允许的全部功能` 删除本机记录，重新跟随环境变量。

### 4.4 UI、交互与信息架构

浏览器不放配置入口。客户端在顶栏放「功能菜单」，即使工具都被关掉也能打开。

配置页按「本地处理」「AI 处理」列出当前部署允许的工具。勾选立即保存。

AI 侧栏先显示检查结果。没有可用模型时写明缺失文件、模型包目录、仓库 `https://github.com/dingdangdog/tucools` 和发布页 `https://github.com/dingdangdog/tucools/releases`。已有部分模型时功能可用，只列出可用的模型或效果。

### 4.5 国际化、主题与响应式

文案只改 `zh.ts`。链接、勾选和停用状态使用现有颜色变量。配置页在窄屏单列，勾选行可点区域覆盖整行。

### 4.6 日志、审计、隐私与安全

功能名单和本机选择都不上传。发布页链接固定为上述仓库，不接受配置文件里的任意网址。

## 5. 失败与恢复

- 外部依赖失败：配置文件读不到时显示全部功能。引擎没有响应时停用当前 AI 功能，提示先启动引擎，不把这种情况说成缺模型。
- 部分成功：抠图或优化只要有一个可用模型就允许处理，并提示尚未安装的文件。
- 重试与幂等：AI 页的「重新检查」再次请求健康接口。改环境变量后需要重启提供页面的进程。
- 用户恢复路径：装好模型后点「重新检查」。客户端误关菜单时从顶栏打开「功能菜单」。

## 6. 兼容、迁移与发布

- 未设置 `TUCOOLS_FEATURES` 时行为与现在一样，全部菜单可见。
- 已有本机主题缓存不受影响。新的缓存键是 `tucools-features`。
- 健康检查响应字段不变。
- 发布前不需要数据迁移。模型仍单独放在发布页，不进入镜像和安装包。

## 7. 验证与观察

- `npm run typecheck` 已通过。`node --check apps/desktop/host.js` 已通过。
- 未启动页面、引擎、Docker 或安装包构建。浏览器里的菜单开关、模型停用和链接未做人工点击验证。
