# 035 让 GitHub 包页面稳定读到镜像描述

**日期：** 2026-10-26

## 背景 / 问题

引擎镜像发布成功后，包版本页仍可能显示 `No description provided`。已发布的 `0.0.3` 索引注解里已经有「图酷图像处理引擎，提供抠图、优化和消除。镜像不含模型包。」公开的包页面和 `0.0.3` 版本页现在能显示这段文字。两份平台清单没有这段注解。索引里还有两份 BuildKit 证明清单，包页面因此把架构显示成 3 个，其中包含 `unknown/unknown`。`0.0.2` 的索引没有描述。原先的检查只看索引注解，证明清单和空白的平台清单不会让工作流失败。

## 变更内容

- 页面镜像和引擎镜像的描述同时写入清单索引，以及 `linux/amd64`、`linux/arm64` 两份平台清单。镜像配置里的 `LABEL` 保留。
- 构建关闭 BuildKit 证明清单，避免包页面多出 `unknown/unknown`。
- 推送后检查索引类型、两端描述和架构列表。描述缺失、描述不一致或出现证明清单时，工作流失败。

## 影响范围

- `.github/workflows/image-reusable.yml`
- `.github/scripts/verify-image-description.mjs`
- `docs/deploy.md`
- `design/008-independent-release-workflows.md`

## 数据库与兼容性

- 无数据库影响。
- 镜像启动方式、标签名和 `linux/amd64`、`linux/arm64` 不变。
- 已经推送的 `0.0.2` 和 `0.0.3` 不会被改写。下一次发布才会去掉证明清单，并把描述写到平台清单。
- 新清单不再包含证明附件。

## 验证

- `node .github/scripts/verify-image-description.mjs` 在 `SELF_TEST=1` 下通过：完整清单通过；缺描述、证明清单、平台清单描述为空或描述不一致时失败。
- 用同一脚本读取已发布的 `ghcr.io/dingdangdog/tucools-engine:0.0.3` 和 `:0.0.2`。`0.0.3` 因证明清单失败；`0.0.2` 因索引没有描述失败。
- 打开公开页面确认：`0.0.3` 和包首页显示上述引擎描述，架构计数为 3；`0.0.2` 没有这段描述。
- 未重新构建或推送镜像。

## 未做事项

- 未改写已经推送的 `0.0.2` 和 `0.0.3`。
