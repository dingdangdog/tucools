# 013 为安装包和网页提供多语言页面与收录

**日期：** 2026-10-24

## 背景 / 问题

图酷只有简体中文。安装包和网页共用同一份页面，公开部署时搜索引擎和生成式引擎也只能读到中文说明。原 easyimage 站点已经按固定前缀提供多种语言，图酷需要同一组语言，同时不能改掉已经在用的中文地址。

## 变更内容

- 增加英语、繁体中文、西语、德语、日语、巴西葡语、印地语、越南语、阿拉伯语和孟加拉语。简体中文仍是默认语言，地址不带前缀。其他语言使用 `/en`、`/zh_hant`、`/es`、`/de`、`/ja`、`/pt_br`、`/hi`、`/vn`、`/ar`、`/bn`。`/zh` 转到无前缀中文。
- 顶栏可以切换语言。网页不按浏览器语言跳转；保存的语言只在打开站点根 `/` 时生效。安装包第一次打开根地址、且没有保存语言时，按系统语言选择。阿拉伯语使用从右到左的页面方向。
- 每种语言的首页和工具页都预渲染独立 HTML，并带 hreflang、JSON-LD 和无脚本说明。站点地图包含 220 条地址和语言互指。每种语言有自己的 `llms.txt` 和 `llms-full.txt`。功能菜单仍是 `noindex`。
- 构建参数 `VITE_SITE_URL` 与容器变量 `TUCOOLS_SITE_URL` 都可以把站内路径写成绝对地址。容器入口同时处理各语言收录文件和页面里的规范地址，不改资源路径，也不会重复加前缀。
- nginx 和安装包静态服务优先返回目录下的 `index.html`，语言前缀下未知页面回退到该语言首页。

## 影响范围

- `apps/web/src/locale.ts`、`content/`、`seo.ts`、`apply-seo.ts`、`router.ts`、`nav.ts`、`features.ts`、`seo-plugin.ts`、`styles.css`
- `apps/web/src/components/LocaleSelect.vue`、`AppShell.vue` 以及读取文案的页面
- `apps/desktop/host.js`
- `deploy/nginx.conf`、`deploy/web-entrypoint.sh`、`deploy/Dockerfile.web`、`deploy/docker-compose.yml`
- `.github/workflows/release.yml`
- `docs/deploy.md`、`README.md`、`AGENTS.md`、`design/005-i18n-seo.md`

## 数据库与兼容性

- 无数据库影响。
- 原有中文地址不变。未保存语言的网页访问者仍看到简体中文。
- 未设置站点根时，收录文件继续使用站内路径。
- `TUCOOLS_FEATURES` 仍只影响浏览器显示。站点地图不按这个变量删减。
- 产品名保持「图酷」。模型文件仍不进入镜像和安装包。

## 验证

- `npm run typecheck`：通过。
- `npm run build:web`：通过。首页标题是「图酷」，`lang="zh-CN"`，`x-default` 指向 `/`。`/en/compress` 的标题是「Compress · 图酷」，`lang="en-US"`，canonical 为 `/en/compress`，简体中文互指为 `/compress`。阿拉伯语首页为 `lang="ar"`、`dir="rtl"`。繁体中文首页为 `lang="zh-Hant"`。`sitemap.xml` 有 220 条地址，不含 `/menus`。`/en/llms.txt` 含 `](/en/compress)`。英文和中文功能菜单都是 `noindex`。
- 用与容器入口相同的替换规则处理构建结果：英文压缩页的 canonical、hreflang 和 JSON-LD，以及站点地图和 `en/llms.txt`，都变成 `https://img.example` 绝对地址。再替换一次没有重复加前缀。样式表的 `/assets/` 地址没有被改写。未启动 Docker，未在容器里执行入口脚本。
- `node --check apps/desktop/host.js`：通过。未打开安装包，未在桌面壳里请求带语言前缀的页面。
- 未启动开发服务器，未在浏览器里点击语言切换、从右到左侧栏或工具操作。
